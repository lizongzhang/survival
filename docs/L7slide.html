7.1 随机生存森林 (RSF)模型简介

  • 随机生存森林 (Random Survival Forest) 模型：随机森林 (Random Forest)在生存分析中的扩展，结合了决策树和集成学习的思想，适用于处理生存时间数据。

  • RSF是一种基于随机森林的扩展，结合多棵生存树预测生存时间或风险。每个树基于随机样本和特征子集构建，输出累积风险函数(CHF)或生存概率。

7.1.1 RSF建模思想

  • 基于生存树的集成：RSF 通过构建多棵生存决策树(Survival Tree)，每棵树基于随机采样的数据子集和特征子集训练。

  • 生存树不同于传统分类树，它的目标是预测生存时间或累积风险函数 (Cumulative Hazard Function, CHF)，而不是简单的分类或回归。

  • Bootstrap 采样与随机特征选择：使用 Bootstrap 方法从原始数据中随机抽样(有放回)，并在每次分裂节点时随机选择特征子集(控制参数 mtry)，增加模型的多样性和鲁棒性。

  • 预测输出：每个树输出个体的生存概率或风险分数，RSF 通过所有树的平均或加权组合生成最终预测。输出包括生存函数\(S(t)\) 或累积风险 \(H(t)\)。

  • 袋外数据 (Out-of-Bag, OOB)：未被抽样到的数据用于验证模型，计算 OOB 误差，评估预测性能。

  • RSF 的建模过程避免了强分布假设(如指数或Weibull分布)，通过非参数方式适应复杂数据模式。

7.1.2 RSF优势

  • 传统生存分析方法(如 Cox、AFT 和竞争风险模型)通常依赖比例风险或特定分布等假设。

  • 机器学习方法通过构建非参数模型，灵活处理非线性、高维特征及交互作用，拓展了生存分析的适用范围。

    • 无强假设：不要求比例风险假设(Cox模型)或特定时间分布(AFT模型)，适合非线性关系和复杂交互效应。

    • 鲁棒性：由于RSF在训练时引入了数据和特征的随机性，并采用了集成多棵决策树的方式，因此它能有效减弱异常值、缺失值和噪声数据对最终结果的影响，从而具备较强的鲁棒性。

    • 变量选择与重要性：自动评估变量重要性(Variable Importance, VIMP)，帮助识别关键预测因子，无需手动筛选。

    • 高维数据处理：适合包含大量协变量的数据集，自动处理特征冗余。

    • 丰富的可视化：提供生存曲线、风险分布、部分依赖图等，直观展示结果。

    • 灵活性：通过调整参数(如 ntree, mtry, nodesize)，可平衡偏差和方差。

7.1.3 RSF局限性

  • 计算复杂度较高：随着树的数量(ntree)和样本规模增加，计算成本显著上升，适用于中等规模数据，效率不及线性模型。

  • 解释性较弱：相较于 Cox 模型的回归系数，RSF 输出的风险评分或生存概率难以直接解释，尤其难以量化交互项的具体贡献。

  • 对超参数敏感：mtry、nodesize 和 ntree 等参数需调优，设置不当易导致过拟合或欠拟合。

  • 对稀疏数据不敏感：在事件稀少或时间分布不均的情况下，分裂标准效果下降，模型性能可能受限。

  • 缺乏统计推断框架：作为非参数方法，RSF 不依赖分布假设，虽适合预测任务，但不易提供置信区间或因果解释。

7.1.4 RSF适用场景

  • 非线性与交互复杂的关系：当协变量与生存时间之间存在非线性模式或高阶交互(如基因表达或影像特征)时，RSF能自动建模此类复杂结构。

  • 高维小样本数据：在变量数远多于样本量的场景(如基因组学研究)中，RSF可自动进行特征选择与维度压缩。

  • 群体异质性显著：当研究对象具有高度异质性，传统模型(如Cox)所依赖的比例风险假设难以成立时，RSF 提供更具鲁棒性的替代方案。

  • 探索性分析场景：适用于变量筛选和预测模型构建，尤其在研究早期阶段有助于发现潜在关联。

  • 竞争风险背景：尽管 RSF并非专为竞争风险设计，但可通过模型扩展(如多状态建模)加以适配。

7.1.5 RSF数据要求

样本容量

  • 最小要求：建议样本量至少为 100-200 个观测值，以确保 Bootstrap采样的有效性。事件数(非删失样本)应至少为50-100，以提供足够的信号。

  • 理想范围：500-1000个样本可获得较稳定的结果，大样本(\(>1000\))进一步提升性能。

  • 限制：样本量过小(如\(\<50\))会导致树分裂不足，模型性能下降；事件稀少可能加剧此问题。

变量个数

  • 最低要求：建议样本量至少为 100–200，以确保 Bootstrap重抽样的稳定性；其中事件数(非删失个案)应不少于50–100，以提供足够的有效信息。

  • 理想范围：500–1000个样本可确保模型稳定性；大样本(>1000)有助于进一步提升预测性能与变量选择的可靠性。

  • 主要限制：样本过少(<50)会导致分裂节点不足、模型不稳定；若事件稀少，则信息量进一步降低，影响模型有效性。

  • 事件-变量比建议至少为 5:1 至 10:1，以降低过拟合风险。

    • 事件是指研究对象经历了我们关注的终点结果，通常是 status == 1的观测，即非删失的样本。

7.2.3 数据预处理

  • randomForestSRC::rfsrc()，定性变量必须设为 factor 类型。

    • 使用 0/1 数值会被当作连续变量处理，导致模型误判变量类型，影响建模效果与变量重要性的解释。

  • rfsrc() 如何判断变量类型？

    • factor 类型 → 视为分类变量，使用基于类别的分裂规则；

    • 数值型变量(包括 0/1)→ 视为连续变量，用于数值型分裂；

    • 字符串类型 → 自动转换为 factor

数据预处理

7.2.4 拟合RSF

RSF()语法结构

rfsrc(formula,
      data,
      ntree = 1000,
      mtry = NULL,
      nodesize = NULL,
      importance = FALSE,
      block.size = 1,
      splitrule = "logrank",
      ...)

  • formula Surv(time, status) ~ x1 + x2 + …

  • ntree 构建的树的数量，默认 1000

  • mtry 每次节点分裂时随机选取的变量数，默认是变量个数的平方根

  • nodesize 每棵树终端节点的最小样本数(生存模型中建议 15–25)

  • importance 是否计算变量重要性

  • block.size 控制高维数据的内存计算效率，建议设为 10–50

  • splitrule 分裂标准，生存模型中默认为 “logrank”

估计RSF模型

# 拟合 RSF 模型
rsf_model <- rfsrc(Surv(time, cens) ~ horTh + age + menostat + tsize + tgrade + pnodes + progrec + estrec,
                   data = gbsg2,
                   ntree = 500,            # 树的数量
                   mtry = 3,               # 变量个数的平方根 
                   nodesize = 15,          # 终端节点最小样本数
                   importance = TRUE)      # 计算变量重要性

RSF模型结果解读

  • Sample size: 686 总样本量为 686，表示模型训练时使用的观察总数。

  • Number of deaths: 299 发生事件(死亡或目标结局)的数量为 299，剩余样本为删失(censored)数据。

  • Number of trees: 500 模型构建了500棵决策树，这是随机森林的核心参数，控制模型的稳定性和泛化能力。树数较多通常提高精度但增加计算成本。

  • Forest terminal node size: 15 每棵树的终端节点(leaf node)最小样本数为15。这是树的复杂度控制参数，防止过拟合。

  • Average no. of terminal nodes:33.166 平均每棵树有约 33.166 个终端节点，反映树的平均深度和复杂度。

RSF模型估计结果解读

  • No. of variables tried at each split: 3 每次分裂时随机选择的变量数为 3。随机森林m模型的关键特征，通过限制变量数量引入随机性，减少相关性。

  • Total no. of variables: 8 模型总共使用了 8 个预测变量。

  • Resampling used to grow trees:swor 使用了“sampling without replacement”(无放回抽样)方法生长树。这确保每个树基于不同的子样本，提高模型多样性。

  • Resample size used to grow trees: 434 每棵树生长时使用的子样本大小为 434(约占总样本 686 的 63%)，这是无放回抽样的结果。

  • Analysis: RSF分析类型为随机生存森林(Random Survival Forest)，专门用于生存数据。

RSF模型估计结果解读

  • Family: surv 模型家族为“surv”(生存分析)，表示处理时间到事件数据。

  • Splitting rule: logrank random 分裂规则基于 log-rank 统计量，带随机性(random)，用于优化节点分裂以最大化生存差异。

  • Number of random split points: 10 每次分裂尝试 10 个随机切分点，增加随机性并提高计算效率。

  • (OOB) CRPS: 395.67263386

    • 外部样本(Out-Of-Bag, OOB)累积预测误差 (Cumulative Rank Probability Score, CRPS) 为 395.67。

    • CRPS 衡量预测分布与实际观测的匹配程度，值越小越好。

  • (OOB) stand. CRPS: 0.16110449 标准化 OOB CRPS 为 0.161。

    • 标准化后值在 0 到 1 之间，0.161 表示中等预测精度。

  • (OOB) Requested performance error: 0.30879613 请求的 OOB性能误差为0.309。

    • OOB 性能误差 与交叉验证或特定指标(如 Brier分数)相关，反映模型预测误差的基准。

计算C-index

  • C-index(Concordance Index，一致性指数)

    • 取值范围为0.5~1.0： 0.5：模型预测与随机猜测无异 1.0：模型预测完全正确，排序无误 C-index越高，说明模型排序预测的能力越强
cindex <- 1 - rsf_model$err.rate[length(rsf_model$err.rate)]
cindex
[1] 0.6929694

循环语句调参

  • ntree 森林中树的数量，通常500-2000, 主要影响方差收敛，对C-index提升作用不大

  • mtry 每次分裂考虑的变量数，可尝试sqrt、log2、全部变量 nodesize # 终端节点最小样本数，调小可提升复杂度，防止欠拟合

  • 中等样本量的数据集上，建议主要调mtry和nodesize，把ntree固定为500或1000。只有在发现模型C-index波动较大时再考虑加大ntree。

调参效果

  • 0.01(1%)的提升：在多数医学、临床等实际生存分析场景中，如果C-index提升≥0.01(比如从0.690提升到0.700)，通常就可以认为有一定的调参效果，尤其是在C-index本身已经不低的情况下。

  • 0.020.03(2%3%)的提升：可以认为是“明显改善”，尤其在样本量较大或原模型表现较好时。

  • ＞0.05(5%以上)提升：通常认为是非常显著的效果，说明调参或特征工程带来了质的变化。

调整随机生存森林(RSF)模型的参数(比如mtry、nodesize等)反复训练模型，但C-index指标(也就是模型的区分能力)并没有显著提高，始终在一定范围内波动。这说明：

  • 模型对参数的敏感度已经不高，也就是说，进一步通过“调参”来提升效果的空间很有限

  • 现有特征(你输入的变量)和数据本身，已经决定了模型目前能达到的最佳效果，模型已经比较“稳定”了

  • 如果你还想让模型表现更好，不应该再把精力放在调参上，而应该

    • 提升数据质量(比如清理异常值、处理缺失、保证标签准确等)

    • 加强特征工程(比如增加有用的新变量、做变量变换、分箱、做交互项、特征选择等

7.2.7 风险分数

  • 随机生存森林(RSF)模型能够为每个个体输出一个生存风险分数，用以衡量该个体发生目标事件(如死亡)的相对风险水平或预期生存时间长短。

    • 风险评分通常是基于累积危险函数(Cumulative Hazard Function, CHF)，即模型为每个个体在各个时间点估计CHF，常用的风险分数是终末(最大)时间点的CHF值。

      • “最大时间点”就是你随访(观察)所有人里，观测到的最长时间，比如有的人活了1年，有的人活了3年，有的人活了5年，那最大时间点就是5年。 对于每一个个体，都可以计算从起点到5年时的CHF值，这就是“终末时间点的CHF值”。

    • 累积危险函数(Cumulative Hazard Function)，它表示“某个个体从起始时间到某个时间点为止，累计的‘发生事件’的危险程度”。

  • 风险分数越高，说明个体累积的危险越大，通常预示其更有可能较早发生目标事件，或者说其预期生存时间较短。

7.3 梯度提升生存模型 (GBM-Survival)简介

7.3.1 GBM-Survival建模思想

  • 梯度提升机(Gradient Boosting Machine, GBM)：是一种集成学习(Ensemble Learning)方法，主要用于回归和分类等任务。它通过将多个弱学习器(通常是决策树)串联起来，逐步提升模型的预测能力。

每一轮训练一个新的弱学习器，用来纠正前面所有弱学习器的预测误差(残差)。最终，所有弱学习器的预测结果进行加权相加，得到最终的模型预测结果。

  • 在生存分析中，GBM 可用于优化多种生存目标函数，包括：

    • Cox 部分似然函数：适用于比例风险假设

    • 排序损失函数：如负对数似然、C-index、pairwise loss，用于优化风险排序或生存预测精度。

7.3.2 GBM-Survival方法优势

传统生存模型(如 CoxPH)面临以下限制：

  • 假设 hazard 与协变量线性相关；
  • 满足比例风险假设；
  • 特征数量较少；
  • 忽略交互作用与非线性结构。

当假设不成立时，预测性能下降。

GBM-Survival 优势：

  • 支持建模非线性与交互关系；

  • 迭代优化提升预测精度；

  • 输出累积危险函数值或部分依赖图，辅助解释。

7.3.3 GBM-Survival局限与挑战

  • 解释性较差：无法像 Cox 回归清晰解释变量作用

  • 超参数敏感：需调参优化，增加建模工作量

  • 计算成本高：样本大时训练耗时

  • 不能直接输出生存概率，需进一步转换

  • 缺失值与时间变异变量处理有限

7.3.4 GBM-Survival适用场景

GBM-Survival 适用于以下任务：

  • 高维/复杂变量结构的数据分析
    • 如基因组、影像、临床大数据
  • 生存时间或事件概率预测
    • 用于患者分层、预后预测、设备寿命建模
  • 模型预测能力要求高
    • 如 AI 医疗、精准医疗等任务
  • 传统模型假设不成立或变量筛选需求强
    • 不依赖比例风险假设，自动处理特征筛选

7.3.5 GBM-Survival数据要求

要素 建议标准
样本容量 最低建议 100–200，推荐 ≥500
事件数/变量比 ≥5–10，避免过拟合
变量个数 推荐 5–50，若 >50 建议预筛选或降维

7.4.4 拟合GBM-Survival模型

gbm()语法结构

gbm(formula, 
    distribution = "bernoulli", 
    data = list(), 
    n.trees = 100, 
    interaction.depth = 1, 
    shrinkage = 0.1, 
    bag.fraction = 0.5, 
    verbose = FALSE, 
    ...)

关键参数解释

  • distribution = "coxph"
    • 含义: 指定使用 Cox 比例风险模型的似然函数作为优化目标，适用于生存分析。
    • 用法: 设为 "coxph" 时，模型基于部分似然估计风险，适合处理生存时间和审查数据(如 Surv(time, cens))。
  • n.trees = 100
    • 含义: 构建的树的数量，控制模型的迭代次数和复杂度。
    • 用法: 值越大(如 100-500)捕捉更多模式，但可能过拟合，建议结合交叉验证调整。
  • interaction.depth = 3
    • 含义: 每棵树的深度，决定变量间交互的阶数。
    • 用法: 设为 3 表示允许三阶交互，增强非线性建模，但过高可能导致过拟合。

关键参数解释

  • shrinkage = 0.1
    • 含义: 学习率，控制每次迭代的步长，影响收敛速度和稳定性。
    • 用法: 0.1 较高，收敛快但可能不稳定，建议降低至 0.01-0.05 并增加 n.trees。
  • bag.fraction = 0.5
    • 含义: 每次迭代中随机采样的比例，引入随机性以增强模型鲁棒性。
    • 用法: 0.5 表示使用 50% 数据训练每棵树，值可调至 0.5-0.7 优化性能。
  • verbose = FALSE
    • 含义: 控制是否打印训练过程中的详细信息。
    • 用法: 设为 FALSE 静默运行，设为 TRUE 可调试模型过程。
# 拟合 GBM-Survival 模型
gbm_model <- gbm(Surv(time, cens) ~ horTh + age + menostat + tsize + 
                   tgrade + pnodes + progrec + estrec,
                 data = gbsg2,

                 n.trees = 100,           # 树的数量
                 interaction.depth = 3,   # 树的深度
                 shrinkage = 0.1,         # 学习率
                 bag.fraction = 0.5,      # 随机采样的比例
                 verbose = FALSE)

7.4.6 风险分数的计算和可视化

风险：某个个体在某一时刻、在所有还未发生事件的个体中，其“马上发生事件的可能性”(也叫瞬时风险、危险率)。

GBM-Survival模型输出的风险分数(f(x))，经过指数变换((f(x)))，就表示该个体的瞬时风险率(hazard)，但通常是与其他个体比较的相对风险。

GBM-Survival模型中的风险分数，是模型基于个体特征计算出的衡量其发生事件风险高低的分值，分数越高风险越大，表示该个体发生事件(如死亡)的风险越高，生存概率越低。

两个个体A和B的相对风比为 \(exp(f(x_A)-f(x_B))\), 险A发生事件的风险是B的\(exp(f(x_A)-f(x_B))\)倍

GBM-Survival模型中的风险分数

个体特征通过GBM模型，经过多轮弱学习器(决策树)加权组合，最终输出一个风险分数。

风险分数(记作f(x))没有单位，可以为正、负或者0，表示这个个体的“风险水平”。

风险分数为0，表示该个体的风险等于基准风险(baseline risk)。也就是说，这个人的风险和“平均水平”或“参考人群”一样。

如果另一个人的风险分数大于0，他的风险就是基准风险的若干倍(>1)；小于0，则风险低于基准(<1)。

如何读懂2D PDP?

  • 颜色梯度：观察颜色从深到浅的变化，浅色区域(如 pnodes > 10 和 age > 60)表示高风险。

  • 等高线解读：等高线密集处(如 pnodes = 5-10)表明风险快速变化。

  • 凸包限制：chull = TRUE 确保仅显示训练数据范围，避免外推。

  • 交互效应：若颜色变化主要随 pnodes 而非 age，说明 pnodes 占主导；若有交叉模式，提示两变量交互。

  • 临床意义：例如，若 age < 50 时 pnodes 影响小，但 age > 70 时风险随 pnodes 激增，可能反映老年患者更脆弱。

7.4.9 个体条件期望曲线ICE Curves

  • Individual Conditional Expectation, ICE, ICE 为每个观测值生成单独的曲线，而不是平均效应，反映 pnodes 对该样本风险的个性化效应。

    • 每个观测值(GBSG2 数据中的行), 在 pnodes 不同值上, 预测的个体的对数累积危险。

  • ICE曲线存在相交说明：存在特征交互效应, 模型对特征X的效应与其他变量有关，存在变量间交互作用。

  • 部分依赖图(PDP)是ICE曲线的均值。ICE曲线大范围相交时，PDP会掩盖不同个体的异质性，PDP的解释力变弱。

                      pred.var = "pnodes", 
                      ice = TRUE,

总结

  • 数据预处理

    • 使用tidyverse::mutate()将定性变量转为factor类型，确保rfsrc()和gbm()正确处理类别变量。

  • RSF模型拟合与调参

    • 使用randomForestSRC::rfsrc()拟合随机生存森林，设置ntree、mtry、nodesize，通过网格搜索优化参数，计算C-index(err.rate)评估模型。

  • GBM-Survival模型拟合

    • 使用gbm::gbm()拟合梯度提升模型，指定distribution=“coxph”，调整n.trees、interaction.depth、shrinkage，通过predict()生成风险分数。

  • 结果可视化与评估

    • 使用ggplot2::ggplot()绘制变量重要性、风险分数分布，survminer::ggsurvplot()生成KM曲线，pdp::partial()绘制部分依赖图，survival::survdiff()进行log-rank检验。
